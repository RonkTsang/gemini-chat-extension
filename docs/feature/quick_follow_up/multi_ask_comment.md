# Follow-up：多选区与评论

状态：代码实现与本地回归完成，真机交互待人工验收。创建：2026-10-19；更新：2026-10-30（界面结构说明）。实现边界与验证记录见[技术方案](./multi_ask_comment_tech.md)。

## 1. 目标与范围

用户可以依次选择多段文本，为每段添加评论，再统一向 Gemini 提问。对外功能名仍为 **Follow-up**，入口仍为 **Ask Gemini**。

本期涉及划词浮层、输入框引用卡片、发送文本协议和历史消息展示。多选区指多次划词后累积，不要求浏览器同时保持多个 Selection Range。界面的布局、层级及外围页面结构由下文直接描述；模型选择、附件、语音和原生发送控件沿用 Gemini，本期不新增这些能力。

## 2. 已明确的交互

### 页面结构与浮层关系

页面分为来源消息区和主输入区。来源消息区保留 Gemini 的回答正文及浏览器原生文字选区；划词胶囊、Quick Comment 和选区编号标记围绕来源文本显示。主输入区位于页面下方，引用卡片排在主请求正文之前。两处通过同一选区的编号关联。

```text
来源消息区
├── 回答正文与当前文字选区
├── 选区附近的编号标记
└── 划词胶囊 / Quick Comment（覆盖显示，不占正文排版空间）

主输入区（沿用原生输入容器）
├── 引用卡片行：Selection 1 → Selection 2 → …（横向滚动）
├── 主请求正文（独立于各卡片评论）
└── 原生操作区：附件入口、模型选择、语音及发送控件
```

全文浮层锚定对应卡片，优先在卡片上方展开；待发送卡片的评论编辑浮层同样锚定该卡片。它们显示在页面内容之上，不挤动卡片行、主请求正文或来源消息。浮层靠近视口边缘时调整位置或翻转，完整内容在限高区域内滚动。

### 选择与卡片

输入容器上部是一行并排的圆角引用卡片，卡片之间留有间距；每张卡片上部显示选中文本预览，底部将评论入口与选区编号成组排列。卡片行下方留出独立的主请求正文区域，底部保留原生操作区。

普通卡片使用细边框区分边界，hover 时以背景变化强调当前卡片，并在右上角显示关闭按钮。完整原文在卡片上方的圆角浮层中展示，标签位于正文之前，浮层通过边框或阴影与背景分层；鼠标可以从卡片移入浮层，不因跨越两者间隙立即关闭。

1. 选中文本，显示原有胶囊及 Ask Gemini 入口。
2. 点击 Ask Gemini，同时向输入框追加 SelectionCard，并将当前胶囊切换为 Quick Comment，允许直接输入。
3. 再次选择其他文本并点击 Ask Gemini，追加新卡片，保留已有卡片和主输入框内容。

SelectionCard 采用固定高度，选中文本最多显示三行，超出以 `...` 结尾。悬停显示完整选中文本；浮层设最大高度并允许滚动，鼠标可以移入浮层操作。输入框卡片悬停时在右上角显示关闭按钮。

### 有评论的卡片与编辑

有评论时，完整内容采用纵向分组：左侧为选区编号，主内容列先显示弱化的 `Selected text` 标签及其下的原文，再通过段间距分隔 `User comment` 标签及评论。原文与评论的内容文字比标签更突出，保留各自的换行；右上角为操作区，按编辑、关闭的顺序排列，并为内容预留空间，避免按钮覆盖文本。深色主题使用深色表面、弱化标签与清晰正文形成层级，浅色主题保持相同结构。

编辑和关闭操作仅用于待发送卡片。历史卡片沿用原文、评论和编号的内容层级，不显示这两个操作。

- 输入框卡片同时外露原文和评论：原文沿用最多三行，评论最多两行，分别超出时以 `...` 结尾；有评论状态需预留两部分内容的固定高度。
- hover 显示完整原文与评论，保留换行，容器设最大高度并支持滚动；外露截断不影响完整内容和发送文本。
- 仅输入框中的待发送卡片可编辑、删除。有 Comment 的待发送卡片在 hover 时，于关闭按钮之前显示编辑按钮。点击后在卡片上方打开轻巧的编辑浮层，包含只读原文和可编辑评论，footer 为 Cancel / Save。
- Save 只更新该卡片的评论、外露预览和隐藏前缀，并关闭编辑浮层；Cancel 放弃本次修改并关闭，保留原评论。编辑浮层与新增评论的 Quick Comment 是两个独立入口。
- 文案复用：Cancel 使用 `common.cancel`（取消）；Save 当前没有 `common.save`，可复用现有 Follow-up 的 `settings.quickFollow.editModal.save`（Save / 保存），不新增重复文案。
- 已发送消息卡片采用相同的原文和评论外露规则、截断及全文浮层，仅供查看，不显示编辑、关闭按钮。

### Quick Comment

Quick Comment 是来源消息区中的圆角评论浮层，贴近当前选区显示，背景与回答正文形成清晰分层。来源文字的选中高亮及附近的编号标记继续可见，帮助用户对应正在评论的内容。评论输入区占浮层主体，并给右侧操作区预留空间；单行状态收起至胶囊高度，多行状态向下增高，确认按钮位于右下角。

确认按钮采用带勾号的圆形按钮。hover 或键盘聚焦时，在按钮附近显示快捷键提示，分为 `Add` 与 `Send` 两行：左侧为动作名称，右侧为对应按键标记；macOS 显示 Enter 与 Command+Enter，Windows / Linux 显示 Enter 与 Ctrl+Enter。语音控件不属于本期评论浮层的新增要求。

| 操作 | 行为 |
| --- | --- |
| 初始显示 | 单行，高度与原胶囊一致，焦点进入评论输入框 |
| Shift+Enter | 换行，容器随内容增高 |
| 点击操作按钮 / Enter | Add：将评论写入当前选区 |
| Command+Enter | 添加当前评论，然后立即发送整条消息 |
| 悬停操作按钮 | 展示 Add / Send 及对应快捷键 |

按钮单行时位于右侧，多行时位于右下侧。中文等输入法处于组词状态时，Enter 不能触发 Add 或 Send。

### 历史消息

识别完整协议后，将每段引用展示为同款卡片，保留各自评论和最终请求。历史卡片复用有评论卡片的展示规则，主请求独立展示；卡片只读，不提供编辑、删除操作。

## 3. 文本协议

固定使用英文标题，与界面语言无关；标题大小写、层级及冒号以以下示例为准：

```markdown
# Selected text:

## Selection 1
> selection text
> selection text has new line

here is the comment

## Selection 2
> selection text 2

here is the comment 2

## My request:
here is the user prompt
```

- Selection 按添加顺序从 1 连续编号。评论可为空；最终请求可为空，支持只针对选区评论后发送。
- 引用的每一行加 `> `，原始空行编码为 `>`，保留换行和原文。三行省略仅影响视觉，不截断实际发送内容。
- 输入框隐藏前缀包含所有 Selection、已添加评论，直至 `## My request:` 后的换行；主输入框可见文字接在其后。
- 添加、评论更新和删除都重新生成唯一前缀，不能累积重复标题；删除最后一张卡片后移除整个前缀，保留主输入框文字。
- 历史识别从消息开头匹配一级标题，依次校验编号、引用块和最终请求标题；进入 My request 后，余下全文均属于请求，不再识别 Selection。
- 不完整或不符合协议的消息保留原文；旧版引用格式继续兼容，不改写历史消息数据。

**协议转义规则已确认：** 引用块在首个无引用前缀的空行处结束。评论中独占一行的 `## Selection N`（正整数）、`## My request:` 加一个前导反斜杠；原本以反斜杠开头的评论行同样再加一个。展示时只撤销这两类约定转义，保证往返无损。评论结尾使用固定结构间隔，保留其自身空行；解析按行和状态进行，不靠宽泛正则切分。完整语法见技术方案。

该协议没有来源标记：用户手写完全相同的结构也会被格式化。这是结构识别的固有限制；若必须区分扩展生成的内容，需要另议标记，不能在实现时擅自加入隐藏协议。

## 4. 交互规则与待确认项

以下交互规则已确认：

| 问题 | 已确认规则 |
| --- | --- |
| Add 后如何继续？ | 保存评论并关闭 Quick Comment，保留卡片；下一次划词恢复胶囊。Add 不发送消息 |
| 空评论能否 Add / Send？ | 允许，选区仍保留；Send 发送全部卡片、评论及主输入框请求，不只发送当前选区 |
| 退出评论、重新划词时怎么办？ | Esc、点击外部或新选区出现时暂存未提交评论，重开可恢复；发送前将当前草稿提交。不要沿用任意 hide 事件直接清空的行为 |
| 删除卡片如何处理？ | 同时删除该选区的评论和草稿，剩余卡片重新编号；内部稳定 ID 不随编号变化 |
| 多卡片及长评论如何布局？ | 卡片单行横向滚动；Quick Comment 达到最大高度后内部滚动，浮层保持在视口内。具体尺寸在实现时按实际输入框校准 |
| Windows / Linux 快捷键？ | Ctrl+Enter 对应 Send；macOS 为 Command+Enter，提示按平台显示 |
| 重复选区与容量？ | 允许相同文字重复添加，最多 10 张卡片；添加第 11 张时拒绝新增并明确提示，已有内容不变，不静默截断。总字符数具体上限尚未确定 |
| 切换会话或刷新？ | 首期仅当前会话内存草稿，不承诺刷新恢复；切换会话清理浮层及草稿，确保不串会话 |
| 自定义 Prompt 与已有卡片并存？ | 无待发送卡片时保持一键发送；有卡片时点击自定义 Prompt，在按钮旁显示“加入草稿 / 单独发送”选择浮层 |

自定义 Prompt 的两个操作：

- **加入草稿**：将本次模板用当前选中文字展开后的完整文本，换行追加到主输入框末尾；保留已有正文、引用卡片和评论，不立即发送，不转换为 Comment。输入框原本为空时直接填入。
- **单独发送**：仅发送本次展开后的快捷 Prompt；先暂存原引用卡片、评论、未提交评论及主输入框正文，确认该消息已提交且 Gemini 已完成输入框清空后恢复，不等待回答结束。原草稿不随快捷 Prompt 发出，也不因该消息提交而被清理。

选择浮层只在有待发送卡片时出现，不新增全局设置、不记住上次选择；关闭浮层不执行操作，也不改变草稿。支持鼠标和键盘。单独发送期间阻止重复提交和草稿修改；明确发送失败时安全恢复原草稿，提交状态不明时保留暂存内容、提示状态，不自动重发或抢先回填。切换会话不向其他会话恢复草稿。

**单独发送异常恢复方案已确认：** 明确未发出的失败安全回滚原草稿；提交不明、清空超时或恢复失败时保留一份暂存并提示，不自动重发、不覆盖新内容。解除临时输入保护；后续恢复前重新检查来源会话及编辑器安全条件，不因超时认定发送成功。

卡片编辑、关闭按钮和全文浮层也应支持键盘聚焦，不能只依赖 hover。编辑浮层在视口上方空间不足时翻转或调整位置；Esc、点击外部均等同 Cancel，关闭并放弃本轮未保存编辑，保留原评论。Quick Comment 点击外部仍暂存内容，两者不可混淆。

### 隐藏内容与删除

- **已确认：** 本期沿用线上空哨兵模式；阻止用户删除隐藏节点列为后续探索，不纳入本期实现。
- **删除目标：** 正文删除至引用边界后，继续退格按卡片逆序逐一删除，同时移除对应原文、评论及评论草稿。最后一张移除时清理所有自有隐藏内容与卡片，不清空仍存在的用户正文。
- **建议方案，待真机验证：** 每张卡片对应一个空哨兵，以稳定 ID 关联；两张卡片使用两个哨兵。`Selected text` 与 `My request` 是共享协议标题，不各自占用删除步骤。多个空节点是否形成独立删除步骤，需在原生编辑器验证；批量删除、撤销和重建须分别处理。
- **讨论中：** 仅正文非空时插入 `## My request:`，清空正文后移除该标题但保留卡片；正文判空建议忽略空白，保留实际内容不裁剪。这会改变第 3 节当前协议，需同时支持无请求标题的历史消息解析，确认前仍以第 3 节为基线。

## 5. 可行性与实现边界

**结论：可行，但不是单纯替换卡片样式。** 核心是将单引用改为有序草稿集合，并确保卡片、隐藏前缀及实际发送消息一致。

基于当前源码的静态核对：

| 现有位置 | 当前行为与改动点 |
| --- | --- |
| `src/entrypoints/content/overlay/quick-follow-up/index.tsx` | 点击 Ask 后关闭浮层并发出添加事件；需增加 capsule / comment 状态及当前选区 ID，重新处理焦点、关闭和浮层动态尺寸 |
| `src/entrypoints/content/lagecy/content.ts`：`addQuoteUI` | 添加前删除旧引用，隐藏文本超过 2,000 字符会截断；需改为集合及统一序列化，取消静默截断 |
| 同文件：`transformQuoteInHistory` | 依赖本地化前缀与分隔符识别单引用；需增加新协议解析及多卡片展示，保留旧格式兼容 |
| 同文件：引用来源及大纲逻辑 | 来源锚点和 `quoteText` 等字段按单引用设计；需明确多选区映射与大纲摘要，不能只改消息外观 |
| `src/utils/editorUtils.ts`：`sendMessage` | 成功仅表示触发发送按钮；不能据此认定 Gemini 已接收消息并立即丢弃草稿 |

建议划分三个职责：纯文本协议解析/序列化、当前会话草稿状态、页面 DOM 适配。草稿保存 `id / selectedText / comment / commentDraft / 可选来源锚点`；主输入框仍由 Gemini 管理，更新前缀时不得覆盖用户已输入文字。

- Quick Comment 继续使用 Chakra UI，留在现有 Shadow DOM 内。
- 输入框和历史卡片使用原生 HTML + CSS，共用卡片构建及样式；使用 `textContent` 写入选区和评论，不将内容直接插入 HTML。
- 新 DOM 查询集中到功能内的 `dom.ts`，实现前按 `docs/agent_guides/gemini-dom.md` 核对实时 DOM 或固定样本；本次没有验证页面运行时行为。
- 隐藏引用文本沿用当前项目既有的输入框承载及发送机制；本次回归多卡片协议、长文本和前缀更新后仍完整发送且仅发送一次，不再将该既有机制本身列为待确认可行性。
- Send 前提交评论并更新前缀；按钮不可用或发送失败时保留内容。只有观察到对应消息提交结果后才清理，期间防止重复触发。
- 单独发送额外保留一份会话内临时草稿快照；恢复需要验证原生编辑器状态、消息确认与清空时序，不仅是重新插入文本节点。暂存不承诺跨刷新恢复。
- 历史渲染必须幂等、可恢复原文，兼容懒加载和节点复用；复制、编辑消息和大纲不能因隐藏原文而丢失内容。来源回跳依赖独立锚点，纯 Markdown 无法恢复历史来源位置。
- 原生卡片不自动保证性能：只更新变更卡片，限制观察范围，避免自身 DOM 更新循环；卸载或切换会话时清理监听器、观察器及浮层。

## 6. 验收重点

1. 连续添加三段文本，各自评论正确关联；删除中间卡片后编号、评论和发送前缀一致，主请求不变。
2. 输入框与消息卡片均外露原文和评论，原文最多三行、评论最多两行，溢出省略；完整内容滚动、操作按钮、键盘访问在明暗主题和窄窗口可用，长文本发送不丢失。
3. Add、Send、换行及输入法行为正确；直接点击 Gemini 发送按钮也包含应提交的评论。
4. 多行引用、空行、空评论、空请求、保留标题和反斜杠完成序列化/解析往返；普通消息及残缺协议不被误隐藏。
5. 发送失败保留草稿，成功只清理对应草稿；切换会话不串数据。
6. 新旧历史消息、懒加载、复制、编辑、消息大纲经过回归验证；无卡片时自定义 Prompt 仍一键发送，有卡片时提供“加入草稿 / 单独发送”，关闭选择浮层不改变内容。
7. 有评论的待发送卡片的编辑按钮位于关闭按钮之前；编辑浮层原文只读、评论可编辑，Cancel 保留原值，Save 同步卡片及发送前缀，不影响其他选区和主请求。已发送消息卡片不显示编辑、关闭按钮。
8. 加入草稿只追加展开后的模板文本，已有卡片、评论、主正文均保留；单独发送不携带原草稿，提交及清空完成后恢复原内容，发送失败、超时、清空延迟及切换会话时不丢失或串入草稿。
9. 第 10 张卡片可正常添加，第 11 张被拒绝且原草稿不变；删除一张后可继续添加。编辑浮层点击外部等同 Cancel，不保存本轮修改。
