# Folders Roadmap

## P1 候选：子文件夹

### 状态

待验证，不纳入 P0 交付范围。

### 目标

允许用户在 Folder 下创建和整理子文件夹，服务于复杂工作流中的多层分类。

### P0 准备

当前 UI 只创建和展示根 Folder。领域模型、Repository 和同步/备份协议已支持以 `ROOT_FOLDER_ID` 表示根节点、保存父子关系、校验树结构及移动 Folder；这属于数据层能力，不代表用户可在 UI 中管理子 Folder。当前不承诺第三方插件的多层文件夹迁移。

### 进入条件

满足以下三类信号中的至少两类后，评估进入 P1：

1. 用户访谈或支持请求明确需要层级组织，而非仅需要更多 Folder。
2. 潜在迁移用户的备份中真实存在嵌套树，且缺少层级会阻碍迁移。
3. P0 用户反馈根 Folder 列表难以管理，并伴随大量重命名、重排或分类需求。

### P1 范围

- 先支持两层结构：根 Folder 与子文件夹；不直接开放无限层级。
- 支持创建、重命名、删除、排序和展开/收起子文件夹。
- 明确定义父 Folder 删除后的子文件夹去向、跨设备同步冲突和导入导出行为。
- 同步与备份必须保留完整层级；迁移无法保真时需明确提示，不得静默扁平化。
